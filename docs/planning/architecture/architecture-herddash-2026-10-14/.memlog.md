- (decision) Paradigm: hexagonal (ports and adapters) around a pure core, with the engine as a single-writer actor. Core = domain rules (Attention Class, Waiting Time, Profile and Context Line rules, ordering) with no I/O; adapters = herdr socket, OS process env, SQLite store, HTTP/SSE, plugin-log importer.
- (decision) Identity: AgentKey = (host, server, pane_id). host = configured name defaulting to OS hostname; server = herdr session name (default 'default') from the socket in use. Every stored row and API path carries all three. Prevents id collisions across machines and named sessions.
- (decision) Record is append-only: transitions and resync markers are inserted, never updated; only the Retention sweep deletes. Each transition stores provenance (live|snapshot|backfill), herdr version, profile, prev/new status, herdr seq where known, observed_at UTC ms. Possibly-spurious flag on pre-0.9.2 backfilled done.
- (decision) Derived values (Attention Class, Waiting Time + lower-bound flag, Context Line, Profile, order) computed only in core, carried in one AgentView type that both /api/state and SSE emit; the Board renders AgentView verbatim and computes nothing except the live clock tick.
- (decision) herdr is reached only through internal/herdr: dial-per-request, one long-lived connection per subscription, subscribe-before-snapshot, snapshot is truth, events only invalidate, reconcile timer, serialized resync. The client exposes no focus method and no output-read method in v1 - the capability is absent, not merely unused.
- (decision) HTTP: GET-only routes on loopback; served from the engine's published view, never a herdr call on demand. SSE has no replay: on (re)connect the client refetches /api/state, then applies events in order of a monotonically increasing view sequence number.
- (decision) Backfill is a subcommand (herddash import-plugin-log) that refuses to run while the Daemon holds the database lock; it writes through the same store package with provenance backfill. Prevents a second concurrent writer.
- (decision) Schema migrations are embedded, numbered SQL applied at start in one transaction; schema version recorded in the DB. Any change to the transitions table is a stored-event-schema change and needs an ADR.

- (decision) Engine seeds from the record (new AD-12): at start and after each resync core folds each Agent's stored history via one store read port into the class-start instant, its provenance and the ever-working fact; each Daemon start is recorded as a resync marker; Retention never deletes the latest Transition or the latest working Transition of an Agent.
- (decision) Exactness rule: Waiting Time is exact only when the Transition that began the current Attention Class was observed live and the Status seen on reconnect is unchanged; otherwise it is a lower bound from the earliest evidence. Backfilled and possibly-spurious starts are always lower bounds. Per FR-8, a restart that changed nothing keeps exact times; PRD glossary wording aligned.
- (decision) Events vs truth: a live status event is recorded at once as a live Transition (observed fact with herdr ordering); the snapshot is truth for the pane set and current Status, and a disagreement is recorded as a snapshot Transition. Buffered events are never replayed onto a snapshot; events arriving during a snapshot read cause another read.
- (decision) Ownership (new AD-11): internal/herdr provides means only (dial, ping, snapshot, subscribe, unsubscribe, stream-health signals); the engine owns the pane set, reconcile timer, resync decision, the one-at-a-time guard, a minimum resync interval, and resync markers. internal/config owns socket path and Server name resolution, used by both serve and import.
- (decision) Ordering: AgentView carries a sort key (zone, class rank, start instant, workspace label, AgentKey); core exports the comparison; the Board may sort by that key and nothing else; a shared golden fixture tests that the Board's order equals core's.
- (decision) SSE: client opens /events first; the server's first event on every connection is a full state event with run_id and view sequence; then agent, removed, transition, resync and connection events in publish order. /api/state serves non-streaming clients. Connection truth shape fixed: connected, last_snapshot_at, herdr_version, gate (ok|advisory|refused), resync_guaranteed.
- (decision) One write path (new AD-13): core.NewTransition is the only constructor and store.Append the only insert, for serve and import alike; unknown values are NULL, never the string unknown; re-import safety via a nullable unique import_key; the operator supplies the date the Host reached 0.9.2 to flag possibly-spurious done.
- (decision) Database ownership uses an advisory flock taken by store.Open for both serve and import, released by the OS on crash. Process umask 077 so WAL and SHM files are owner-only. WAL journal mode. A database whose schema version is newer than the binary refuses to start.
- (decision) Profile is resolved synchronously before an Agent's first Transition is recorded, with a bounded timeout that yields unresolved; re-resolved on agent detection and when herdr reports a foreground process change. Pane-to-process call and the change signal are UNVERIFIED until milestone 1. darwin needs golang.org/x/sys for kern.procargs2; added to ADR-0004.
- (decision) Pane id stability across a herdr restart is UNVERIFIED: every row carries a server_epoch, part of AgentKey, so a reused id cannot splice histories; how a new herdr server instance is detected is a milestone-1 finding and blocks fixing ADR-0005's columns. v1 observes one herdr server per Daemon; the key already allows several.
- (decision) HTTP hardening: reject requests whose Host header is not a loopback name (DNS rebinding); GET / matches only the root; unsupported methods get the JSON error shape; SSE clears the write deadline.
