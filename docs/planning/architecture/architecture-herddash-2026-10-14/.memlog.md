- (event) Run started 2026-10-14, Fast path, purpose build substrate plus human explainer for later publication; inputs docs/prd.md (final), PRD addendum, ADR-0001..0003, docs/research.
- (version) Go: stable 1.27.2 and 1.26.9 as of 2026-10-15 (go.dev/dl); Go 1.25, which CLAUDE.md names as minimum, is now outside the two-release support window.
- (version) modernc.org/sqlite v1.60.1 (2026-09-29, proxy.golang.org) - pure-Go SQLite driver.
- (version) github.com/BurntSushi/toml v1.6.0 (2025-12-18, proxy.golang.org).
- (version) herdr latest v0.9.4 (2026-10-13), repo moved to herdrdev/herdr; release notes mention no socket API change. Operator machine still 0.8.2.
- (constraint) Inherited from PRD/ADR-0001/0003: read-only, loopback, never focus, never read pane output in v1, one Daemon per Host, subscribe per pane, snapshot is truth, Profile recorded per Transition, Retention 90d, single binary, no npm/build step.
- (constraint) CONTRIBUTING/CLAUDE threshold: new dependency, change to how herdr is spoken to, stored event schema, new network surface each need a numbered ADR; spine cites ADR numbers rather than restating.
- (decision) Operator 2026-10-15: one engine goroutine owns current state and is the sole SQLite writer; herdr client, timers and import send it messages; HTTP reads an immutable view it publishes. Prevents two writers and ordering bugs. Alternative rejected: mutex-shared map with many writers.
- (decision) Operator 2026-10-15: SQLite driver modernc.org/sqlite (pure Go). Rejected ncruces/go-sqlite3 (wasm runtime, smaller user base) and mattn/go-sqlite3 (cgo breaks trivial cross-compilation). New dependency -> ADR.
- (decision) Operator 2026-10-15: config file is TOML via github.com/BurntSushi/toml; matches herdr's own config format and is hand-editable with comments. Rejected stdlib JSON (no comments). New dependency -> ADR.
- (decision) Operator 2026-10-15: go.mod requires go 1.26; releases built with the newest stable (1.27.x). CLAUDE.md and CONTRIBUTING updated from 1.25.
- (decision) Paradigm: hexagonal (ports and adapters) around a pure core, with the engine as a single-writer actor. Core = domain rules (Attention Class, Waiting Time, Profile and Context Line rules, ordering) with no I/O; adapters = herdr socket, OS process env, SQLite store, HTTP/SSE, plugin-log importer.
- (decision) Identity: AgentKey = (host, server, pane_id). host = configured name defaulting to OS hostname; server = herdr session name (default 'default') from the socket in use. Every stored row and API path carries all three. Prevents id collisions across machines and named sessions.
- (decision) Record is append-only: transitions and resync markers are inserted, never updated; only the Retention sweep deletes. Each transition stores provenance (live|snapshot|backfill), herdr version, profile, prev/new status, herdr seq where known, observed_at UTC ms. Possibly-spurious flag on pre-0.9.2 backfilled done.
- (decision) Derived values (Attention Class, Waiting Time + lower-bound flag, Context Line, Profile, order) computed only in core, carried in one AgentView type that both /api/state and SSE emit; the Board renders AgentView verbatim and computes nothing except the live clock tick.
- (decision) herdr is reached only through internal/herdr: dial-per-request, one long-lived connection per subscription, subscribe-before-snapshot, snapshot is truth, events only invalidate, reconcile timer, serialized resync. The client exposes no focus method and no output-read method in v1 - the capability is absent, not merely unused.
- (decision) HTTP: GET-only routes on loopback; served from the engine's published view, never a herdr call on demand. SSE has no replay: on (re)connect the client refetches /api/state, then applies events in order of a monotonically increasing view sequence number.
- (decision) Backfill is a subcommand (herddash import-plugin-log) that refuses to run while the Daemon holds the database lock; it writes through the same store package with provenance backfill. Prevents a second concurrent writer.
- (decision) Schema migrations are embedded, numbered SQL applied at start in one transaction; schema version recorded in the DB. Any change to the transitions table is a stored-event-schema change and needs an ADR.
