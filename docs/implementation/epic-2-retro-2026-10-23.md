### Diff-scope review: story-boundary defects

**F-1. Two Agents that share a pane id fold together after a Daemon restart.** (VG, ADV, ECH;
holds at HEAD.) Disposition: **fix**.

- Source: `Store.History` selects by `(host, server, epoch, pane_id)` only
  (`internal/store/record.go:186-196`). `core.Fold` and `FoldResult.Add` never start over at a row
  with no previous Status (`internal/core/attention.go:53-80`). `firstSight` folds the whole
  history and writes nothing when the last row's Status and Agent Program match
  (`internal/engine/engine.go:2279-2295`).
- Trigger: in one run, an Agent is released and a new one is detected in the same pane. The usual
  case is quitting `claude` and starting it again in that pane, and a terminal replacement does
  the same. Story 2.4's triage #1 gives the new Agent a fresh fold *within the run*. Its rows,
  though, go under the same AgentKey as the old Agent's. After the next Daemon restart with the
  epoch kept, the pane is seeded from both Agents' rows. Worked through:
  - Agent A goes working, then done at T1 (live). Agent B is then first seen idle at T2.
  - After the restart, the fold over A's and B's rows says Finished since T1, live, so exact.
  - B is idle and so is the last row, so nothing is written.
  - The Board shows B as Finished, exact, waiting since A finished, where before the restart it
    showed Working (never worked) since T2.
- Second trigger, same root (ADV, ECH): a pane id reused on a new terminal *while the Daemon was
  down*. Any other pane that kept its terminal keeps the epoch (`decideEpoch`). `onSnapshot`
  overwrites `e.terminals` before `apply` (`engine.go:1142`). The `replaced` check in `apply` only
  sees panes tracked in memory, and none are after a restart, so
  `p.seedHistory = resubscribe && e.historic && !replaced` (`engine.go:1269`) seeds the new Agent
  from the old one's history.
- Retention keeps the key's highest-id `working` row (`internal/store/sweep.go:41-51`), which may
  be A's, so the record keeps `EverWorking` true for B.
- Why no test caught it: `TestWaitingRedetectedReadsNoHistory` and
  `TestWaitingTerminalReplacedReadsNoHistory` (`internal/engine/attention_test.go:261-292`) stop
  before any restart. Every restart test (`TestWaitingRestart*`,
  `TestRetentionKeepsFoldAcrossRestart`, `TestServeRestartKeepsWaiting`) seeds one Agent per key.
- Upstream lesson: Stories 2.2 (key), 2.4 (seeding) and 2.5 (sweep floor) each assumed one Agent
  per AgentKey within an epoch, and no story owned that assumption. AD-3 promises "an Agent on
  another terminal is another Agent", but the record has no field that says so.

**F-2. A failed `SaveServerState` does not stop the rows that follow it.** (ADV, ECH; holds at
HEAD.) Disposition: **defer**.

- Source: `saveState` logs the error and returns (`internal/engine/recorder.go:95-110`), and
  `onSnapshot` goes on to mark and `apply` (`engine.go:1144-1167`). So rows can be keyed by an
  epoch the store does not hold, which is what `restore`'s own comment says it is avoiding.
- Story 2.3's triage #13 already rejected this as low ("logged and retried at the next snapshot").
  The retro records it because Story 2.2's commit message claims more than the code does: "saved
  before a snapshot's rows ... recording is off for the run rather than risking a wrong epoch"
  (`b72f192`). Only a failed *load* turns recording off.
- Upstream lesson: commit and PR text should state guarantees only as strongly as the code
  provides them.

**F-3. A resync that is scheduled or queued when the connection drops is never marked.** (ECH;
holds at HEAD.) Disposition: **accept**.

- Source: `disconnect` marks causes only when `e.resyncing` is set. It discards `resyncNext` for a
  scheduled resync or one queued behind a running one (`engine.go:810-823`).
- Story 2.3's commit `f8ffd3f` claims "one marker per distinct cause ... also when a disconnect
  cuts it short".
- Accepted because the code comment states this is deliberate, and the `reconnect` marker the
  next snapshot writes records the gap anyway (FR-7 holds). The commit claim is wider than the
  code.

**F-4. A first-sight row can be stamped live at a snapshot's time.** (ECH; holds at HEAD.)
Disposition: **defer**, investigate first.

- Source: `seen` restamps `seenAt` only when the Status changes, but always overwrites `seenBy`
  (`engine.go:2257-2264`).
- Trigger: a pane is seen by a snapshot, and then, before its Profile resolves, a live event
  repeats the same Status. Its first-sight row is then `live` with the snapshot's time, so its
  Waiting Time shows as exact when it is only a lower bound.
- How often this happens depends on whether herdr's status subscription sends the current Status
  on subscribe. That was not checked here.

**F-5. Retention deletes resync markers by age, including those inside a present Agent's kept
span.** (ADV, ECH; holds at HEAD.) Disposition: **defer**.

- Source: `sweepMarkers` is `DELETE FROM resync_markers WHERE observed_at < ?1`
  (`internal/store/sweep.go:53-55`). Rows from `Since` onward are kept for a present Agent.
- Only reachable for an Agent that has stayed in one class for longer than Retention (90 days by
  default). Its history would then show no gap where one was recorded.

**F-6. Recording silently off for the run when saved state fails to load.** (ADV; holds at HEAD.)
Disposition: **defer**.

- Source: `restore` sets `e.store = nil` and logs one error (`internal/engine/recorder.go:36-40`).
- This was Story 2.2's deliberate choice (triage #1). The retro's point is narrower: nothing on
  `/api/state` or the Board says the record is not being written, so the Daemon looks healthy.

**F-7. The import summary does not say which Host and Server the rows were filed under.** (ADV;
holds at HEAD.) Disposition: **defer**.

- Source: the summary line seen in Behavior verification. The Server comes from the socket path or
  session (`internal/config/config.go`). An interactive shell inside a herdr pane inherits
  `HERDR_SOCKET_PATH`, which may differ from what launchd or systemd gives `serve`.
- Story 2.6's triage #2 made a corrected re-run possible, but nothing shows the operator that a
  re-run is needed.

**F-8. A Retention tick skipped during a resync has no catch-up.** (ADV; holds at HEAD.)
Disposition: **defer**.

- Source: `sweep` returns when `resyncing || resyncScheduled` (`internal/engine/retention.go:59`),
  and the next attempt is a full `retentionSweepInterval` (1 h) later.
- Only matters on a Host where resyncs recur often enough to keep landing on the tick.

**F-9. A first sight that matches the record writes no row even when the Profile changed.** (ADV;
holds at HEAD.) Disposition: **accept**.

- Source: the skip at `engine.go:2295` compares Status and Agent Program only.
- Story 2.2's acceptance criterion asks only that Transitions written *after* a Profile Map edit
  carry the new Profile, which holds.
