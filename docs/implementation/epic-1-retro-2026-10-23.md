### Diff-scope lenses (story boundaries)

**L1. Medium-high: a Transition after an Agent Program change carries the new program and the old
Profile** (1.5/1.9 boundary). In `onStatus` on a known pane, `setProgram` (`engine.go:1012`,
`1628-1647`) sets `p.program` and starts an asynchronous `resolve`. The Transition is then
recorded at once through `transitionAt`, which writes `Profile: p.profile`, still the old one
(`engine.go:2221-2225`). Since Story 2.2 that row is persisted, and the record is append-only
(AD-4). Introduced in `0f38886`; holds at HEAD. Reachable when a pane switches agents, for example
`claude` exits and `codex` starts in the same pane. *Fix now (CODE).*

**L2. Medium: a replaced terminal reuses the old AgentKey** (1.6/1.7 boundary). When a pane id
shows a different non-empty `terminal_id` within a kept epoch, `apply` removes it ("terminal
replaced") and tracks it again (`engine.go:1253-1262`). The spine says this "is another Agent"
(`ARCHITECTURE-SPINE.md:136`), and the code's comment says "never join the two". But the AgentKey
is `{host, server, epoch, pane}`, so both Agents' Transitions share one key, one history and one
Waiting-Time fold. Introduced in `88fb175`; holds at HEAD. Fixing it means either a boundary in the
record that history and fold honour, or a key change (a stored-schema change, so an ADR). *Needs an
operator decision (see Action items).*

**L3. Medium: snapshot failures after ready never escalate.** `onSnapshot` logs "snapshot failed;
reading again" and retries every `snapshotRetryDelay` forever while the lifecycle stream stays up
(`engine.go:1100-1107`). Nothing marks the picture stale. Reconcile goes through the same path, so
it fails too. Introduced in `a3838be`/`88fb175`; holds at HEAD. *Fix now (CODE): after N
consecutive failures, treat it as `lost()` so ConnectionTruth reports it.*

**L4. Low-medium: a malformed lifecycle event forces a full reconnect** (1.4/1.6 boundary). An
unknown kind or a missing pane id returns `errUnexpectedEvent` (`internal/herdr/map.go:190`,
`203`), which `subscribe.go:203` reports as `HealthUndecodable`. `onLifecycle` then calls `lost()`
(`engine.go:926-932`). If a newer herdr sent such an event repeatedly, the Daemon would flap,
because the gate has no upper version bound. Holds at HEAD. *Fix now (CODE): log and resnapshot
for a well-formed but unexpected event; keep `undecodable` for unparsable JSON.*

**L5. Medium, partly verified: `agent_detected` for a new pane drops the program.** `onLifecycle`
calls `track(ev.PaneID)` without setting the program (`engine.go:970-972`). A first status event
naming no program then reaches `report(p)` with an empty program (`engine.go:998-1004`). The code
path is confirmed; the reported effect (empty program and Profile, then a spurious Profile change)
was not reproduced. *Fix now (CODE): a test first, then store `ev.AgentProgram` at detection.*

**L6. Medium: a reconnect that keeps the epoch never re-resolves Profiles.** `apply` does not call
`resolve` for kept panes, so an agent restarted under another Profile while herddash was
disconnected keeps its old Profile until the next `agent_detected`. No test covers it
(`TestProfileReconnectDuringRedetect`, `engine_test.go:2028`, takes a different path). *Fix now
(CODE): add the test and decide; re-resolving every Agent on reconnect is cheap.*

**L7. Low: Profile values equal after `filepath.Clean` can both pass validation.**
`config.go:576-580` cleans only absolute values before the duplicate check, while
`core.ResolveProfile` cleans every key and ranges a map (`internal/core/profile.go:39-44`), so a
collision resolves nondeterministically. Only relative values are affected. *Fix now (CODE, small).*

**L8. Low: Profile reads use `e.runCtx`, not the connection's context, and the read goroutine is
outside `e.wg`** (`engine.go:1677-1684`). A `process_info` call can outlive a gate refusal or
disconnect by up to `profileTimeout`. The abandonment is deliberate (see the comment there); only
the context is questionable. *Defer (low).*

**L9. Low, grouped and unverified beyond the code reference**: a snapshot first sight stores a
Status outside the five without validating it (`engine.go:2257-2262`; the live path checks
`Valid()` at `engine.go:1009`); a set-but-empty variable gives `unresolved`, not the absent case
(`profile.go:36-46`); Profile Map keys match by exact case (`config.go:519-528`); a literal `~` in
an observed value never matches (`profile.go:39`); the darwin `procargs2` parser is untested with an
empty argv[0] (`internal/procenv/procenv.go:111-114`); Profile names may equal program names
(`profile.go:32-35`). *Defer: one `deferred-work.md` entry.*

**Rejected lens finding.** "An explicit `server` is never checked against the socket path"
(`socket.go:104-106`): spec-1-2 lines 62-63 make "an explicit `server` always wins" the
specified behaviour, and `docs/config.example.toml:43` documents it. *Accept.*

**Known items the lenses re-observed and excluded**: pane move as removal plus new Agent (5.8),
epoch persistence (fixed in `b72f192`), darwin CI (5.7), Profile retry (5.4), `gen` confinement and
`HerdrOrder` (5.5), the 1.5 rejection loop (resolved by 1.7).

### Process lessons (from story specs, commits and vfkb; session transcripts were unavailable)

**P1. A deferral routed "to Story N" can vanish.** spec-1-3 #25 went to Story 1.5 and was never
picked up (A6). The `deferred-work.md` entry existed, but Story 1.5's spec was not written from it.
*Lesson: when a deferral names a future story, add it to that story's ACs in `epics.md` at the same
time, or route it to `deferred-work.md` only.*

**P2. An architecture "Open" item had no owning story.** AD-3's "Nothing persists the evidence yet
... Milestone 2 persists both" was assigned to no Epic 2 story. The Story 2.1 review caught it
(`deferred-work.md`, spec-2-1 entry), and Story 2.2 built it (`b72f192`, vfkb `225eddaa1b00`).
*Lesson: every spine item marked Open needs a story or a deferred-work entry when the epics are
cut.*

**P3. A flaky fake-client race lived for five days.** Story 1.5's fake signalled a snapshot call
before reading its gate. About one run in 40, `TestNewAgentLiveBeforeSnapshot` hung until the
10-minute test timeout. It was fixed in `175dd68` (#43). Story 1.7 found a similar latent race only
under `-race -cpu=8` (spec-1-7 Implementation Notes). *Lesson: run a new engine concurrency test
with `-race -count=50` (or `-cpu=1,4,8`) before merging.*

**P4. The deferred-work ledger has no "resolved" marker.** At least 4 of Epic 1's 13 entries are
resolved (1.2 #3, 1.2 #21, 1.5 #3, and the epoch-persistence entry) but read as open.
*Defer: Story 5.8's last AC.*

**Wins the evidence supports.** Story 1.3 replaced documentation claims with observations from an
isolated herdr 0.9.5 binary (`docs/research/herdr-0.9.5-probe.sh`, `herdr-socket-api.md:294-430`).
That settled the epoch rule, the one-request-per-connection rule and the Profile trigger before any
